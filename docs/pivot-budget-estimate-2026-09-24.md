## 规模草案和复用规则

| 项目 | 用于估算的草案 | 边界 |
|---|---|---|
| 主研究问题 | 100 个审计合格的 GlobalOpinionQA 问题 | 所有已定条件复用同一批；100 是规划起点，不是功效分析结论 |
| 阵容与 tone | 6 套阵容 × friendly/neutral/hostile | 不换型号，不减少 judges |
| 重复 | 2 次独立初始生成和随机 routing 计划 | 每次内部三种 tone 复用同一初始回答及路线；独立主题仍是 100 个，不是 200 个 |
| 讨论规模 | 每场最多 24 个唯一回复节点、3 个末端分支、路径长 12 | 随机 routing 预先规划、稀疏分叉；该上限组合可实现，但具体分叉分布未定 |
| B/C | 三位 judges 分别评全部正式记录 | C 文本相邻比较加首末比较；末端重复的相同文本对可复用 |
| A 消融 | 每场预先随机抽 2 个节点，retained/removed 都重新生成 | 不按已经观察到的 agreement 或效果挑节点；这里只是抽样量草案 |
| D | 对既定跨家族配置的开放成员，预算先覆盖全部合格节点 | 同一记录上的自报 agreement 与 C/D 配套；不扩到其他阵容 |
| E | 每场 debate 一个 synthesis；每题/阵容/重复一个 no-debate synthesis | 精确复用正式初始回答；同一 no-debate 答案与三种 tone 比较 |
| 人工核查 | 起点建议 B 60 条 + C 60 对，共 120 项/人 | 两人独立评同一批；覆盖阵容/tone，非每格独立验证；按 1–2 分钟/项粗估每人 2–4 小时，另留校准时间 |

这些数目连同抽样、路由上限都待用户确认。人工核查不因三个 LLM judges 或多个分支自动翻倍。5 题试跑单独计费，不计入这 100 个主研究问题；若改 protocol，不能悄悄把调参样本当作独立正式验证。

### 调用数量如何得到

- 正式讨论：100 题 × 6 阵容 × 3 tone × 2 次 = 3,600 场；按每场用满 24 个新节点估计，共 86,400 条正式回复。
- 正式初始回答：100 × 6 × 2 × 3 成员 = 3,600 份，在 tone 间复用。初始 C 测量也按这 3,600 份计，不复制成三个独立 baseline。
- C 测量生成：3,600 次初始 + 86,400 次参与后；不为未参与成员补造 position。ragged 记录仍按 `[trajectory_id][member_id][time_index]` 存储，保留 T 和参与次数。
- B：86,400 条主回复 × 3 judges。C：86,400 对相邻记录，另预留最多 3,600 × 3 分支 × 3 成员 = 32,400 对首末记录，每对由 3 judges 评。首末计数是费用上限占位，实际可复用相同记录对，不能造不存在的末端测量。
- A：3,600 × 2 个抽样节点 × 2 个指令条件 = 14,400 条额外回复。本估算还预留三位 B judges 对这些消融回复的评审费 $680；这项是保守预算占位，不表示已经新增必做分析，也未加 C/D 消融测量。
- D：随机 routing 在预算上按接收成员对称计算。M-Qwen 有 2 个 D 成员，M-Opus 有 1 个，合计预期 14,400 个接收事件；D-text 需要 28,800 次 argument/filler 读数。D-choice 另预留每次测量一次前缀评分，包括初始，共 15,000 次。真实数量跟 routing 而变，不强制每成员等长。
- E：3,600 次 debate synthesis + 1,200 次 no-debate synthesis；3,600 个答案对 × 3 judges × 2 呈现顺序。两个顺序不是独立问题。
- 将这些独立评分请求全部计入，约 923,400 次逻辑请求。Batch API 可以调度这些请求，但这里没有预先计入折扣；也未将多个评审样本塞进同一个 judge 上下文来减少费用。

## 账单 token 假设

下面每项是**平均输入/计费输出 token**，输出含可见文字和隐藏推理。它们不是已测量的长度、不是给模型设置的 max_tokens，也不是已批准的 reasoning 配置。

| 调用 | 轻量 | 中心 | 高用量 |
|---|---:|---:|---:|
| 正式回复 / A 消融回复 | 4,000 / 900 | 8,000 / 1,800 | 16,000 / 4,500 |
| 参与后 C position | 4,500 / 350 | 8,500 / 700 | 16,500 / 1,800 |
| B judge，单模型/单样本 | 1,600 / 400 | 2,000 / 1,000 | 3,500 / 3,000 |
| C judge，单模型/单文本对 | 1,000 / 400 | 1,400 / 1,000 | 2,200 / 3,000 |
| D-text，单分支读数 | 4,500 / 200 | 8,500 / 500 | 16,500 / 1,500 |
| E debate chairman | 12,500 / 1,500 | 18,000 / 2,500 | 35,000 / 6,000 |
| E judge，单模型/单顺序 | 2,400 / 400 | 3,200 / 800 | 5,000 / 2,500 |

中心上下文是假设正式可见回复约数百 token，并保留该分支历史；chairman 读取最多 24 个唯一新节点与三份初始回答，不重复展开共享前缀。隐藏推理 token 计入费用，不按“最终只输出标签”假定费用接近零。不同 tokenizer 的实际计费长度由试跑 usage 核查。

初始 prompt、no-debate chairman、额外候选评分前缀等完整假设见计算脚本。这里只建议用试跑账单与少量样本词数校准量级，不恢复用户已否决的每次请求 tokenizer 长度门槛。

## 中心情景费用拆分

每项费用都是 `调用数 × (输入 token × 输入单价 + 计费输出 token × 输出单价) / 1,000,000`，混合委员按已定六套阵容及随机接收机会计算预期。

| 项目 | 估算美元 |
|---|---:|
| 初始回答与正式讨论 | 2,801 |
| C 的选项/完整观点测量生成 | 2,020 |
| B：三位 judges | 4,082 |
| C：三位 judges，相邻及首末比较 | 5,132 |
| A 消融生成及额外文本评审预留 | 1,136 |
| D：选项评分与 argument/filler 认同读数 | 786 |
| E：chairman 合成与三位 judges 双顺序评审 | 632 |
| **合计** | **16,590** |
| **另加 30% 预留后** | **21,570** |

Judges 合计约占 62%。尤其是 B/C，每个 judge 每项平均多用 1,000 个计费输出 token，在这个规模上就会增加约 **$7,412**；这比几百美元的措辞或候选读取优化更影响总账单。高用量情景不是费用上限。

## 敏感性与不包含的费用

- 50/100/200 题、其他草案参数不变：中心主调用费用约 $8,295 / $16,590 / $33,180；加 30% 后约 $10,783 / $21,567 / $43,134。改变题数不是改变统计独立单位的定义。
- 100 题从两次运行改为一次，中心费用也约 $8,295，但回答的重复稳定性问题不同；这是成本参考，不是擅自减少已讨论的设计。
- 两个未核实 Qwen 型号的实际输入/输出价若均是代理价的一半或两倍，中心总额约 $15,828 或 $18,113。代理价不是正式报价，也没有保证实际价格落在此区间。
- Native Inkling 促销结束会使其所列单价翻倍；Sol/Gemini 当前优惠也有时间条件。跨促销期应重算，不能用现在的价格保证未来账单。
- 缓存和 Batch API 的潜在节省未计入；重试、筛题、端点调试及小量补跑放在 30% 预留内。该预留是规划约定，不保证覆盖任何故障或价格变化。
- 不包含人工工资、已有 GPU 的机会成本、自托管 GPU/存储/工程费用、税费及不可预知的平台费用。现阶段不能据本表断言自托管一定更便宜。
- 两个 Qwen 精确型号尚缺已核实的 Tinker 托管可用性。费用可先估，但完整流程的可运行性仍需解决；不换模型来掩盖此问题。
- 推理输出、真实上下文长度、稀有 agreement 档位的样本支持和正式统计精度都未测量。100 题只是建议起点，不承诺每个细分组合都足以得出精确结论。
