## 规模如何得到：每个数字都只是报价假设

| 项目 | 报价假设 |
|---|---|
| 正式问题 | 50 个，共享于三套阵容及三种 tone |
| 重复 | 每个条件一次，没有第二次独立重复 |
| 单场讨论结构 | 两条各含 6 次正式回复的末端轨迹，共享前 3 次回复 |
| 唯一新回复数 | `3 + (6−3) + (6−3) = 9`；初始回答另计 |
| 正式讨论场数 | `50 × 3 阵容 × 3 tone = 450` |
| 正式回复总数 | `450 × 9 = 4,050`；共享前缀不重复生成或计数 |
| B/C 前置抽样 | 在 50 题中随机选一半，即 25 题；这批题在各阵容/tone 的讨论内完整跟踪 |
| A 指令消融 | 每场抽中的讨论预选 1 个节点，两种指令都重新生成；评审另留预算 |
| D | 仅这批抽中问题的混合阵容开放成员，跟随 C 测量节点 |
| E | 全部 450 场讨论都做最终合成与双顺序单 judge 比较；150 份 no-debate 合成跨 tone 复用 |

两条轨迹是一次分叉后的两条末端路径，不是两场独立讨论。这里用一个共享 3 个节点、两个长度为 3 的后缀把讨论规模讲清楚；不是把旧的 24 改名为新默认，也不是默认每位成员均匀参加两次。接收者仍按预先规划的随机 routing，ragged 记录不变。

B/C 主分析按该回复的四档 **self-reported agreement** 分组，tone 可合并，仅保留为来源字段及必要的检查维度。上表保留抽中 25 题的三种 tone 是配套抽样的报价假设，不要求各 tone 分别凑独立显著性的样本量，也不对同一文本按三个 tone 反复评审。更稀疏的讨论块抽样仍可进一步减少成本，未在本报价中暗中采用。

## C、judge 和 D 的调用数

- 初始正式回答：`50 × 3 阵容 × 3 成员 = 450`，三种 tone 共用。
- 抽中的讨论：`25 × 3 阵容 × 3 tone = 225` 场；共 `225 × 9 = 2,025` 条回复。
- C：`25 × 3 阵容 × 3 成员 = 225` 次初始测量，加 2,025 次参与后 choice+完整 position，共 **2,250 次生成**。未抽中的讨论不做这些测量，额外输出不回流正式讨论。
- B：2,025 条回复，各评一次。C：2,025 对相邻记录，加最多 `225 × 2 末端轨迹 × 3 成员 = 1,350` 对首末记录，共最多 3,375 对，各评一次。B/C 总计 **5,400 次单 judge 调用**。相同文本对可复用，不为没有参与的成员补造末端测量。
- A 消融：225 个预选节点 × retained/removed，共 450 次额外回复，另预留同一 judge 的 450 次文本评审；没有新增 C/D 消融测量。
- D：按随机接收机会对称，混合阵容的 675 条抽样正式回复中，两个开放成员预计接收 **450** 条。D-text 因而需 **900** 次 argument/control 读数。实际数量由 routing 决定，不强制每位相等。
- E：450 次 debate synthesis、150 次 no-debate synthesis；450 个答案对 × 两种顺序 = 900 次 judge 调用。
- 若每次 D-choice 都要补一次候选评分，包括初始共 500 次，则总共约 **15,950 次逻辑请求**。候选概率能随 C 完整返回时，省掉这 500 次。

### D 哪部分可以没有额外调用？

**D-choice：**在 C 输出原题选项的位置读取完整候选概率。如果生成接口已经返回所有候选的读数，则额外分析只是离线计算，无需再次调用模型。Tinker 的 `topk_sample_logprobs` 支持返回采样位置的 top-k，但不保证原题所有选项都在 top-k 内；缺项不能默认为零。

接口也有 `target_prompt_logprobs`，可对指定位置的一组 token 评分。必要时重放 C 的准确前缀（含适用的推理/模板状态），在一次额外 prefill 中补齐候选，而非每个候选各做一次完整生成。本报价保守预留了每次 D-choice 一次补评分，中心约 **$5.15**；若无需补评分，删掉这项即可。实际 API 的采样前/后概率定义、模板、候选 token 和同次返回的附加计费仍须实测；现有文档不构成端到端验收。

**D-text：**固定接收前的完整自身观点，在相同的前置上下文中分别加入真实 peer argument 或近似等长 filler，再读七档认同概率。这与 C 生成“当前自己的选项及观点”不是同一个请求。两次读数仍需模型计算，中心约 **$10.87**。不先生成对 argument 的新回复，不额外写一段 position，也不是另外跑一场 debate。七个候选可成组读取，不默认七次完整生成。

## 缓存和 token：没有用更短输出掩盖费用

沿用旧估算的中心 token：正式回复平均输入 8,000、计费输出 1,800；C 输入 8,500、输出 700；B/C judge 输出 1,000；D-text 输入 8,500、输出 500。输出均包含推理，是未测量的假设，不是已定生成设置。chairman 也沿用平均 18,000 输入、2,500 输出，尽管本次树明显更短。

中心缓存情景仅对讨论、参与后 C、A 消融、D 读数假设 **50% 输入 token 命中缓存**；不是 50% 请求，也不是整个账单打五折。初始回答、初始 C、judges 和 chairman 不预设任何缓存节省。OpenAI 5.6 的未命中可复用输入保守按写入价 1.25×计，命中按 0.1×；Tinker 命中按原生目录 0.2×。不额外预设 Batch 折扣。

正确的缓存前缀、角色、模型后端、断点、缓存寿命和路由尚需验收，50% 只是情景假设。即使完全不使用缓存，报价也仍约 $310；这次降价主要来自较小讨论规模与前置抽样。

### 其他规模和情景

- 同样 50 题、25 题 B/C 样本：缓存禁用约 $310，启用但零命中约 $330，50% 命中约 $264，80% 命中约 $225；均未加预留。
- 主研究增至 100 题，但 B/C/D 样本固定 25 题：中心约 **$431 / $560（含预留）**。A/E 题目变多，B/C 的独立主题数仍是 25，不能说所有层样本都翻倍。
- 两条路径各延长到 12 次回复、仍共享前 3 次，唯一回复数变为 21；其余不变时中心约 **$517 / $672（含预留）**。这是长度敏感性，不是另一个已定协议。
- 两个核心变化要分别认：正式回复从旧假设 86,400 降至 4,050；C 从 90,000 降至 2,250；B/C judges 从 615,600 降至 5,400。降幅不只来自六套变三套，还来自题量/重复/讨论长度的**未批准报价假设**以及单 judge 和前置抽样。
- Qwen 代理价减半/翻倍，中心总额约 $254/$286。确切端点可用性不由费用估算保证。Inkling/Sol/Gemini 有促销期限，执行时须重算。
- 3 题全部做 B/C/D 的完整小试跑，中心约 $22，加预留约 $28；仅为报价，不授权运行，也不计入正式 50 题。

25 个 B/C 独立主题不是功效分析结论，罕见 agreement 档位可能仍缺样本。省钱不能证明每个比较都有足够精度。若加大样本或讨论深度，应直接重算，不能因总价好看就锁定规模。
