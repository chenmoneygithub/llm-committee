**80题与统计支持：**用户问扩展到 turns 后是否已经足够。80题可以作为预算折中的工作规模，但不能由 turn 数证明把握度充足。同题/分支的多条回复相关，共享前缀不增加新样本；更多 turns 能帮助测量过程和降低部分题内生成噪声，却不能替代新问题带来的主题覆盖。跨题不确定性应保留题内/分支依赖。若每题变异相近、其他设计不变，100减至80时标准误粗略乘 `sqrt(100/80)≈1.118`，约增12%；这不是功效分析结果，也不承诺能检出任意效应。09-25改为覆盖80题的turn抽样，扩大了B/C/D计划的跨题覆盖，但某一agreement档位或D适用成员未必覆盖全部80题；必须报告实际题目和事件支持，不能用全池大小替代分组支持。剩余分析/试跑环节应检查题间变异、标签频数和目标精度，不擅自增跑或删已观察结果。

B/C/D主问题按当前回复的自报agreement对齐分析：文本是否实质支持/反驳、自身观点如何变化以及适用开放成员的概率变化。tone不作为必须拆分的主表维度或抽样配额，仍保留为元数据；这不是断言tone在科学上不会影响B/C/D，也不把自报agreement与变化的关联当作因果效应。D-choice若C同次返回完整候选概率则无需额外调用，但仅top-k可能缺项；D-text的argument/filler对照仍需两个额外输入。Chairman输入按唯一正式节点计，分支状态不混合。没有启动付费调用。

**题目筛选已确认沿用现有论文（2026-09-24）：**用户要求保留原筛选规则，确保题目确实适合辩论。80题指通过筛选后选入主研究的题目，不是直接从原始库随机取80条。保留能够围绕外部议题用理由支持或反对的价值判断、评价、偏好或态度题；排除仅报告个人经历、习惯、知晓程度、身份等私有事实的题目。例如，原稿保留对“A university education is more important for a boy than for a girl”的态度题，排除“In the last five years have you traveled to another country other than Canada or Mexico?”这一经历题。资格不取决于模型实际是否争论、是否改变立场，也不增加“必须存在明显初始分歧”等事后筛选条件。

## 1. 已确认的研究结构与新约束

- 所有主研究继续围绕同一批 GlobalOpinionQA 问题，不为 D 另换一批命题或独立的模型集合。
- 已确认实现原则：同一题、阵容、tone、重复运行内，只生成一份正式分支讨论记录供各层复用，不为 A/B/C/D 各重跑一场 debate。D 的选项分支与 C 共用同一节点的 choice+position 测量及其实际输入，分别分析已输出的选择/文本与选择位置的候选概率。D-text 则固定完整 position 原文及接收前上下文，比较加入实际 argument 与近似等长中性填充后的整体认同概率；不拆解为单句核心主张。它是额外认同探针，不能误称为同一个 choice prompt 免费提供的读数。额外测量和评审调用仍需计入预算，详见第 6 节。
- A：自报 peer agreement；包含预设 tone 比较和匹配的 instruction ablation。消融的保留/移除两边均重新生成回复。
- B：一个 LLM judge 判断回复是否实质性地支持/反驳同伴；用户因预算已取消全量三 judge，具体型号待定。
- 新 C：同时记录原题选项变化，以及同一 judge 对自身观点文本变化的判断。选项比较不需要 judge 或人工标注；人工核查限于 B 和 C 的文本判断。
- B/C 文本人工核查目标为两位独立标注者，已获用户确认；先由用户本人开始，第二位之后独立标注同一批样本。样本量、第二位人员与具体标注规则尚未定，尚无已完成标注或双人一致性结果。
- 人工核查已确认采用跨阵容、tone 的随机子样本，不依据模型是否有分歧选样；用户强调人工负担必须有限。整体覆盖条件，不要求每个组合都达到可单独统计的样本量，也不扩成全量标注；具体总量后续按可投入时间与检查目的确定。
- C 的获取方式已确认：在当前分支上下文副本上记录所选选项与简短自身观点；保留成员最初的独立回答和该分支正式发言历史，额外测量答案不回流到讨论或后续测量。历史按 trajectory/member 分开，分叉继承前缀后独立追加。
- C 描述辩论过程中的立场变化及其与认同/反驳的关系。目前不增加 private revision / 独立重答对照，也不声称已将同伴信息的因果贡献与再次生成分离。
- 同一题、同一阵容的 friendly / neutral / hostile 共用一组独立、未加 tone 的初始回答；开始交流后各自发展。
- routing 允许受控分叉，不是全连接，也不是禁止分叉。用户已确认：同一题、同一阵容、同一次重复内，预先随机规划接收者与分叉位置，friendly/neutral/hostile 共用该计划；不根据生成后的 agreement 标签改路由或分叉。具体随机抽样规则、链长和分支数尚未冻结。
- 分支不能混合立场状态。每个分支继承父节点的状态快照，之后独立更新；不同分支不能放进一次调用里再共同更新一个全局 member opinion。
- C 既分析分支内变化，也比较分支间结果；同时记录讨论链位置和该成员第几次参与。初始独立回答记为第 0 次，未再次参与的成员不凭空增加一次测量。
- 已接受用分支上限和最大链长控制规模。此前的 15 是例子，不是已批准的上限。统一调度、原子预留分叉名额、API 并发与轨迹预算分开，是当前建议的实现方式。
- D 只用于跨家族配置的开放权重成员：第一套测 Qwen 和 Inkling，第二套只测 Inkling；其他部分覆盖全部配置。不为凑齐每套两个 D 模型而增加成员或扩大到其他对照组。
- D 的定位是 C 的 probability-level extension：在同一场 debate、同一成员与分支上下文下增加原题选项概率读数，不再是一套独立实验。“补充分析”不自动意味着放附录；具体指标与论文组织尚未定。
- 最终质量比较保留；no-debate 合成逐字复用实际讨论的三份正式初始回答。用户已接受 chairman 使用全部正式讨论内容：50K–100K tokens 可接受，不希望达到 200K。最新要求用前几个样本的词数粗估规模，不必每次请求做 tokenizer 校验；具体输入与长度检查方式见第 6 节。尚未实际测量请求长度。

### 一张 GPU 能否服务多个模型

可以，但两个不同模型通常是两个服务进程/endpoint，共享显存和计算资源。需要同时容纳两套权重、各自的 KV cache 与运行时缓冲。两个服务不能各自默认预留整张卡的 90% 显存。

例如 Qwen-27B + GLM-4.7-Flash 的 BF16 权重粗估约 114 GB，完整 B200 从权重容量看可以考虑同卡共存；剩余空间是否够实际历史长度和并发，需要压测，不能承诺两者都保留独占整卡时的速度。同一 Qwen 型号的三个逻辑成员则只需一份权重，不属于“加载三个不同模型”。

## 5. 预算控制和运行前验收

六套三人阵容不保证比五套四人阵容更便宜。受控 routing 下，费用由实际新增节点数、不断增长的上下文、测量调用及 judge 调用决定。

预算至少拆成四项：

1. Debate 生成与 GPU 占用时间，包括初始回答和各分支新增节点。
2. C 的独立选项测量及 D 的概率读取，不反馈到后续讨论。
3. A 的指令消融：每个抽中的上下文有保留/移除两个新回复。
4. B、C 的单 judge，以及最终答案的合成和评价。逐节点各一次 B 和 C 相邻文本判断，另计 C 首末比较与 E 双顺序评审；采用离线批处理可降低调度开销，不能把这些调用漏出预算。此项已按用户最新预算要求由三 judge 改为单 judge。

分支预算（包含已完成路径的总量）与 GPU/API 并发分别管理。只有中央调度器分配分叉名额；模型 worker 不根据看到的剩余名额自行扩展。分叉继承不可互相修改的状态快照，存储每个节点更新前后的 own position 和实际输入。

正式运行前需要小规模工程验收，以下目前均未执行：

- 核对 GPU 型号、实际可见显存、软件兼容性和权重访问权限。
- 检查模型的结构化 agreement、回复和 own-position 输出；缺失值必须显式记录，不能用默认 agreement 标签填成有效结果。
- 验证 D 能得到所有候选选项标签的概率，而不只是某次输出的 top-k；核对 tokenizer、输出位置、模板和 reasoning 设置。
- 以计划的历史长度测试端点的峰值显存、吞吐、超时和排队，估算 GPU 小时及所有 API token 费用。
- 检查多个分支同时出现同一成员时，输入和状态仍完全隔离；分叉不突破预算，失败重试不重复记节点或重复预留名额。

用户明确纠正：“应该是生成一次观点。在 context 里加上另一 member 的 argument，然后询问有多认同自己的观点。然后再比较控制组。”因此撤回助手上一轮为 D-text 提出的“固定前次/初始主张，再比较两个参与时点”的方案；该方案没有获用户批准。原题选项分支的纵向比较不因本轮修正而自动取消。

- 用户要求的核心设计：只生成一次待评价的自身观点 S，固定接收当前 peer argument 之前的分支上下文 H。两份独立副本共享完全相同的 H 和 S，一份加入另一成员的实际 argument，一份使用控制输入；然后都询问对同一 S 的当前认同程度，读取认同等级概率。
- 核心比较是同一节点上 argument 与 control 的差，不是初始与当前或前次与本次上下文的差。两边都不能另生成一份观点来替换 S，也不把自己刚表达的观点在参照端默认设为满分认同。
- 延续“一份正式 debate，多层复用”：从正式讨论和已有观点记录取 H、S 及实际 peer 消息，不为 D 另造命题池、初始回答、专门反方或另一场讨论。用户已明确 S 使用完整 position 原文（见下），不抽取单句核心主张、不拆解理由或删去限定条件。
- 控制输入已确认：用户回复“可以，next one pls”，接受近似等长、不讨论议题的中性填充消息，用它替换 argument，其他上下文保持一致。不再将无新增消息作为本项未决选项。旧稿实句为“The moderator noted the time and reminded participants that further remarks would follow in due course.”，旧实现按 token 长度比取整重复，非精确等长；该句和算法可供复用，最终 prompt 与长度匹配实现尚待细化。
- 读数时机按用户描述是加入 argument/control 后直接做认同探针，不先生成一段对消息的自由文本回复再测量。这与 C 已定的正式参与后 choice+position 读数并非相同测量位置；复用同一 debate 事件和数据，不再声称 D-text 与 C 是完全相同的 prompt 或同一 API 调用。
- 可在指定 trajectory 节点建立这种局部对照并保留 T/成员参与索引，但测哪些节点和观点参照尚未定；不能将各节点 argument–control 差相加冒充起点到终点的累计变化，也不能据此自动把 C 或 D-choice 改为另一套干预实验。
- 认同探针及控制输入只用于隔离的测量副本，不扩展为正式讨论分支，不向委员会、后续 C 测量或 chairman 回流。完整 position 的引文只作为独立 D 探针的被评价对象，不变成成员记忆。额外测量调用须纳入预算，但不重跑完整 debate。
- 只读核对本地论文 `sections/setup_logprob.tex` 与 `sections/appendix_logprob.tex`：旧 D 确实使用同一初始回答的 argument/filler 双输入和 A--G 认同概率，但其被评价对象是预先编写的原始命题。新版测自身观点是对象上的变化，不能称旧稿已经测过同一对象；也不是对整段文字算生成概率。
- 七档认同读出可沿用其方法思路，但确切标签、数值摘要、read temperature、节点抽样及检验仍待定；control 已定为近似等长中性填充，具体句子和匹配实现另行细化。不自动恢复 top-two margin 或 entropy matching。读数是对指定整段观点的条件性整体认同响应，不是客观文本语义距离或真实信念。
- 本轮只按用户纠正更新规划，没有修改论文或实现、运行模型或扩大人工标注；不自动推进下一项。

#### 已确认：D-text 直接使用完整 position，不拆分主张与理由

用户明确拒绝助手的结构化提案：“the position as the full text is the opinion. no need to break it down”。撤回“一句核心主张 + 简短理由”的新增格式要求；不能在后续实现或写作中恢复为既定方案。

- 保留 C 已定的 choice+position，position 是完整的自身观点文本，包括其理由、限定条件及其他原有内容。不增设必需的 claim/rationale 字段，不要求单句化，也不让其他模型摘要、改写或提取一句话代替原文。
- D-text 的 S 直接取接收当前 argument 之前已保存的完整 position；argument/control 两份测量副本引用逐字相同的 S。两边不重新生成观点，也不使用收到该 argument 后的新观点作参照。具体节点抽样及初始/最近一次记录的选择规则仍待运行协议细化。
- C 的文本 judges 比较前后完整 position；D-text 询问接收 argument 或 control 后，对指定整段 position 的整体认同程度，并读取认同等级概率。可用措辞示意：“你目前在多大程度上认同以下整段观点？”确切 prompt 和量表尚未冻结。
- 助手原先拆分的考虑是避免对结论与理由认同不同造成歧义，但用户要测的对象就是整段 opinion，因此不以消除该歧义为由改变对象。分数解释为对整段观点的整体评价，不能推出每个子论点都以同样方向或幅度变化；若材料确实无法评价，其处理规则另定，不默默拆解。
- 全文仅作为独立 D 探针中的被评价引文，不回填正式讨论、后续 C 测量或 chairman 输入。也不是计算完整 position 本身的生成概率。
- 本项按用户要求记录为使用完整原文；D 的量表/数值摘要仍待决定。只修改规划，没有修改论文或实验代码、运行模型或增加人工标注；不自动推进下一项。

#### 已确认收尾项 1/3：D 两个分支的数值，按对应 agreement 分组

用户回复“可以”，接受下面的计分，同时强调必须与成员在对应 turn 的自报 agree level 配套汇总，而不是盲目 aggregate。计分与该分组原则现已确认；统计权重与检验仍属于后续统一分析计划。

- **D-choice：**每一对比较固定参照端实际选中的选项 a_ref，报告 `100 * (p_current(a_ref) - p_reference(a_ref))`，单位百分点。逐次比较的参照是该成员前次参与，初始比较的参照是初始记录；不是所有比较都只追踪初选，也不是在比较两端各自换成当前最高概率选项。保存完整概率向量；单项差不概括其他选项之间的全部重分配，不对任意原题选项编号取均值。
- **D-text：**七档按从完全反对到完全赞同的 1--7 编码，使用前述七档标签草案（中立为 4，具体 prompt 用语待统一细化）。在 argument/control 两个输入下分别由七档概率计算加权平均认同分 `mu(p) = sum(k * p(k))`，再报告 `mu(argument) - mu(control)`。正数是相对 filler 更认同原整段观点，负数是更不认同；不是统一定义为朝对手移动，也不是时间前后差。
- 假想例子：filler 条件平均认同分为 6.3，argument 条件为 5.6，则差为 -0.7 个量表分。这个均值采用等距编码约定，不是认同下降 70%、真实信念距离或段落中每条论点的独立变化。完整七档概率同时保存。
- 两个分支采用候选内归一化、未作额外 read-temperature 重标定的记录概率（read temperature=1）；不将 top-two margin 或 entropy matching 作为本次主指标。API 实际概率定义、候选 token 覆盖、缺失/无效输出等需要在最终 protocol 和端点验收中明确，不能将 top-k 漏项当作零概率。
- 计分方案获确认不表示将不同模型、tone 或 agreement 档位直接池化成一个平均值。对应事件与分组要求见下；没有运行模型或修改论文/实验代码，下一组仍等用户明确要求。

#### 已确认主分析要求：同一回复事件的 self-reported agreement 与 C/D 配套

用户给出的例子是 member 1 在某一 turn 表示不同意 trajectory 里的上一条说法，然后看它自己的 position 如何变化。主分析要直接回答“表达这种 agreement/disagreement 时，自身观点发生了什么变化”。

- 以真实回复事件绑定数据：同一 question/config/tone/repetition、trajectory/node、接收成员、被回复的 peer 消息及 reply。自报标签取该成员这条正式 reply 的 A 标签，不取上一位发言者或其他分支的标签。稀疏 routing 中以实际 reply-to/parent 消息标识确定对象，不能只按全局完成时间找上一条消息。
- 与这一事件绑定的 C 记录比较该成员自己的前次与本次 choice/position；D-choice 使用同一对测量的概率；D-text 的处理消息必须是这条 reply 所回应的实际 peer argument，其 control 为匹配 filler。D-text 恢复该 argument 输入前的上下文做局部对照，不把之后生成的实际 reply 或自报标签补进该探针。
- 分组标签来自实际正式回复，先生成并保存，再离线与测量结果对齐；不把它作为 D probe 的新增条件，不为 filler 副本额外造一条正式回复或 agreement 标签。这里不要求不同层的调用按某个在线顺序串行执行，只要求事件和上下文精确对齐。
- 主要按自报完全赞同、部分赞同、部分反对、完全反对四档，分别报告 C 的选项切换比例、文本变化类别分布（均分为辅），以及 D 的相应概率差/认同分差；缺失自报标签单列。B 的外部判定是另一种已记录读出，不能静默替换或混入自报标签成为同一分组标准。
- 保留阵容、接收模型、tone、T 及成员参与次数，避免未经说明把不同条件池化；每组同时保留有效问题和记录支持量。不自动要求所有维度的笛卡尔积都做独立显著性检验或新增样本，确切分层/标准化、权重及不确定性在分析计划统一确定。
- 这首先是描述性条件分组：表达反对不必意味着自身立场改变，表达赞同也不必意味着此前持反对意见。不能把生成后观察到的 agreement 标签当作随机分配的原因，或将相关性写成“自报反对导致立场移动”。
- 逐次变化与当前 reply 标签配套；初始到终点的整段轨迹结果继续单独保留，不能将同一最终差复制给沿途所有 turns 并当作独立结果。共享前缀也不重复充当独立样本。累计结果具体如何与标签历史关联，留在同一份分析 protocol 中明确，不新增一轮单独议题。
- 本轮收口第 1 组：计分及 agreement 分组要求已定。还剩实验规模/抽样/预算，以及分析/试跑两组；不自动推进。
